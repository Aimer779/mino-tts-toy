# Handoff Write: 回写交接文档

任务暂停前，把本轮状态回写到 `harness/handoff.md`。记录完成项、验证结果、残留问题、下一轮目标。保证下一轮能直接接着干。

## 触发条件

- 会话即将结束
- 完成一个阶段性目标
- 需要暂停，下次继续
- 会话上下文即将被压缩
- 用户说"暂停"、"写 handoff"、"交接一下"

## 标准流程

1. 总结本轮完成的工作
2. 记录验证结果（基于证据）
3. 列出残留问题
4. 定义下一轮最小目标
5. 写入 `harness/handoff.md`

## 输出格式

写入 `harness/handoff.md` 的内容：

```markdown
# Handoff - [YYYY-MM-DD]

## 本轮完成
- [具体完成项 1]
- [具体完成项 2]

## 验证结果
- [x] 构建：[命令] 通过
- [x] 测试：[命令] X/Y 通过
- [x] 手动：[具体操作]，确认 [现象]

## 残留问题
- [未完成项 1]
- [未完成项 2]

## 下一轮最小目标
[用一句话描述下轮要做什么]

## 恢复指令
请先读：
1. harness/spec.md
2. harness/handoff.md
3. [相关源代码文件]

## 关键决策
- [本轮做出的重要决策及其原因]
```

## 规则

| 场景 | 做法 |
|------|------|
| 会话结束前 | 必须写 handoff，不能跳过 |
| 阶段完成 | 写 handoff + 归档到 `harness/archive/` |
| 残留问题为空 | 要确认是否真的全部完成，不是遗漏 |
| 下一轮目标太模糊 | 细化到具体动作，不能写"继续完善" |

## 禁止

- 不要说"我记住了，下次继续"（没写文件）
- 不要跳过残留问题
- 不要把下一轮目标写得太模糊（"继续完善"）
- 不要忘记恢复指令（下次还得重新探索）

## 后续动作

handoff 写入完成 → 会话可以安全结束
下次会话 → 从 `handoff-recover` 开始恢复状态

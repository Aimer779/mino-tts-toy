# Redefine Goal: 根据证据重定义目标

执行过程中遇到意外时，先停。根据真实证据重新定义本轮最小目标。不要硬闯，不要顺手扩展范围。

## 触发条件

- 执行过程中出现 504/403 等运行时错误
- 日志/测试暴露了之前没发现的问题
- 原计划走不通，需要换路线
- 用户说"先停"、"目标偏了"、"范围太大"

## 标准流程

1. 停止当前执行
2. 分析真实证据（日志、测试、错误信息）
3. 重新定义本轮最小目标
4. 输出重定义报告，等待用户确认

## 输出格式

```
## 目标重定义

### 原目标
[原本这轮要做什么]

### 发生了什么
[基于日志/测试/错误信息的客观描述]

### 新目标
[本轮只做什么，比原目标更小、更聚焦]

### 搁置项
- [暂时不做的内容]
- [等新目标完成后再继续的内容]

### 下一步动作
1. [具体动作 1]
2. [具体动作 2]

等你确认后，我再继续。
```

## 规则

| 场景 | 做法 |
|------|------|
| 日志报错 | 先定位原因，不改代码 |
| 任务太大 | 重新压成最小可验证的一件事 |
| 用户说"先停" | 立即停止，输出当前状态 |

## 禁止

- 不要说"我顺便把这个也修了"
- 不要把新目标定得比原目标还大
- 不要基于猜测而非证据
- 不要跳过搁置项

## 后续动作

新目标确认后，进入 `check-before-execute` 重新校准。问题解决后，进入 `verify-by-evidence` 验证结果。

# Verify By Evidence: 用证据说话

不接受主观判断。模型声称完成后，必须提供客观证据：构建结果、测试输出、手动验证现象。"应该没问题"不算完成。

## 触发条件

- 模型说"我改好了"
- 模型说"应该没问题"
- 模型说"逻辑是对的"
- 用户说"验证一下"、"跑测试"、"证据呢"

## 标准流程

1. 跑构建命令，贴输出
2. 跑测试命令，贴输出
3. 手动验证，描述看到的现象
4. 检查副作用，确认其他功能未受影响
5. 输出验证报告，等待用户确认

## 输出格式

```
## 验证报告

### 构建
命令：`[具体命令]`
结果：✅ 通过 / ❌ 失败
输出：[粘贴关键输出]

### 测试
命令：`[具体命令]`
结果：✅ X/Y 通过 / ❌ X/Y 失败
输出：[粘贴关键输出]

### 手动验证
操作：[具体操作步骤]
现象：[实际看到的现象]
结论：✅ 符合预期 / ❌ 不符合预期（描述差异）

### 副作用检查
- [功能 A]：✅ 正常
- [功能 B]：✅ 正常
- [功能 C]：✅ 正常

### 结论
[基于以上证据，本轮目标是否完成]
```

## 规则

| 场景 | 做法 |
|------|------|
| 模型说"应该没问题" | 要求跑测试，贴输出 |
| 模型说"我看了一下代码，逻辑是对的" | 要求实际运行，不要只看代码 |
| 测试失败 | 进入 `redefine-goal` 重定义目标 |
| 构建失败 | 先修复构建问题，再继续 |

## 禁止

- 不要接受"应该没问题"
- 不要接受"我觉得好了"
- 不要接受"逻辑是对的"（没跑过怎么知道）
- 不要跳过副作用检查

## 偏航信号

如果出现以下情况，说明验证不合格：

- 模型说"应该没问题"（主观判断）
- 模型说"我看了一下代码，逻辑是对的"（没跑测试）
- 模型跳过验证，直接开始下一个任务
- 验证只覆盖了"能跑通"，没覆盖"边界情况"

## 后续动作

验证全部通过 → 进入 `handoff-write` 写交接文档
验证失败 → 进入 `redefine-goal` 重定义目标，或继续修复
